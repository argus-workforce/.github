# Contributing

## Language

English is the working language for code, comments, commits, pull requests, issues, and documentation. User-facing product copy in Dutch and English lives only in translation files, with English keys.

## Development workflow

We use trunk-based development on `main`. The `main` branch is always releasable. Keep branches short-lived, for a few days at most. Put unfinished work behind a feature flag.

Do not create `develop`, `release/`, or `hotfix/` branches. Create a hotfix on a `fix/` branch from `main`.

Use these branch prefixes:

- `feat/`, for example `feat/ARG-42-match-score-explanation`
- `fix/`
- `chore/`
- `refactor/`
- `test/`
- `docs/`
- `ci/`

## Pull requests and commits

Squash merge only. The PR title becomes the commit message and must follow Conventional Commits: `type(scope): description`.

Types: `feat`, `fix`, `chore`, `refactor`, `test`, `docs`, `ci`, `perf`.

Scopes: `matching`, `schedule`, `hours`, `auth`, `tenant`, `ui`, `api`, `mobile`.

For breaking changes, use a `!` after the type and scope, such as `feat(api)!: change response format`, or include a `BREAKING CHANGE:` line.

Changelogs and versions are generated by release-please from these titles.

Every PR to `main` needs one approval and green checks for PR hygiene, quality, and end-to-end tests where applicable.

## JavaScript and TypeScript naming

Write variables, parameters, functions, and imports in full and make their purpose clear. Use `context`, not `ctx`; `event`, not `e`; and `@use '…' as tokens`, not `as t`.

These established terms are allowed: `xs`, `sm`, `md`, `lg`, `xl`, `API`, `URL`, `ID`, `UI`, `i18n`, `e2e`, `HTTP`, `JSON`, `CSS`, and `SCSS`. Folder names such as `src`, `dist`, `docs`, and `config` are also allowed.
